# Поисковый каталог

Учебный проект по дисциплине «Основы веб-разработки», **вариант 10**.

Многостраничный веб-сайт — каталог полезных интернет-ресурсов
с разделением по темам, административной панелью, журналированием
действий пользователей и парольной защитой служебных страниц.

**Выполнила:** Мальцева Елизавета Максимовна, группа 8ВМ61
**Год:** 2026

---

## Использованные технологии

| Технология | Назначение |
|---|---|
| Node.js 18+ | среда выполнения JavaScript на сервере |
| Express 4 | веб-фреймворк, маршрутизация запросов |
| EJS | шаблонизатор, формирование HTML на сервере |
| SQLite (better-sqlite3) | база данных в одном файле |
| express-session | хранение сессий администратора |
| bcryptjs | хеширование паролей |

Внешние библиотеки на стороне браузера не используются:
оформление выполнено собственной таблицей стилей,
интерактивные элементы — средствами обычного JavaScript.

## Запуск проекта

### 1. Установка зависимостей

```bash
npm install
```

### 2. Заполнение базы данных

```bash
npm run seed
```

Команда создаёт файл базы `data/catalog.db`, добавляет 6 тем,
43 ссылки (включая 2 скрытые — для проверки работы ЛБ 3)
и учётную запись администратора.

### 3. Запуск сервера

```bash
npm start
```

После запуска сайт доступен по адресу **http://localhost:3000**

### Учётная запись администратора

| Логин | Пароль |
|---|---|
| `admin` | `admin123` |

## Структура проекта

```
poisk-catalog/
├── data/                     файл базы данных и хранилище сессий
├── logs/                     журнал действий пользователей (ЛБ 6)
├── .vscode/launch.json       конфигурация отладчика (ЛБ 8)
└── src/
    ├── app.js                точка входа, настройка сервера
    ├── config.js             параметры приложения
    ├── models/
    │   ├── database.js       подключение к базе, создание таблиц
    │   └── seed.js           заполнение начальными данными
    ├── repositories/         слой доступа к данным (SQL-запросы)
    │   ├── linkRepository.js
    │   ├── topicRepository.js
    │   └── adminRepository.js
    ├── services/             слой бизнес-логики
    │   ├── linkService.js        операции со ссылками
    │   ├── authService.js        вход администратора (ЛБ 7)
    │   ├── logService.js         журналирование действий (ЛБ 6)
    │   └── validationService.js  проверка исходных данных
    ├── middleware/           промежуточные обработчики
    │   ├── auth.js               проверка доступа (ЛБ 7)
    │   └── locals.js             общие переменные шаблонов
    ├── routes/               маршруты
    │   ├── catalogRoutes.js      пользовательская часть (ЛБ 1–2)
    │   └── adminRoutes.js        административная часть (ЛБ 3–7)
    ├── views/                шаблоны EJS
    │   ├── pages/                пользовательские страницы
    │   ├── admin/                административные страницы
    │   └── partials/             повторно используемые фрагменты
    └── public/               статические файлы
        ├── css/style.css
        └── js/
```

Приложение построено по слоистой схеме: маршруты принимают запрос,
сервисы выполняют бизнес-логику и проверку данных,
репозитории обращаются к базе. SQL-запросы содержатся только
в репозиториях и не встречаются в других частях приложения.

### Пользовательская часть

| Адрес | Назначение | Лабораторная работа |
|---|---|---|

## Журнал действий (ЛБ 6)

Действия записываются в файл `logs/actions.json` в формате JSON:
каждая строка файла — отдельная запись.

Пример записи:

```json
{
  "timestamp": "2026-09-12T14:32:07.412Z",
  "date": "12.09.2026",
  "time": "14:32:07",
  "level": "info",
  "action": "LINK_CLICK",
  "actionLabel": "Переход по ссылке",
  "actor": { "type": "guest", "login": null, "ip": "127.0.0.1" },
  "target": { "entity": "link", "id": 23, "title": "GitHub" },
  "details": { "url": "https://github.com", "topic": "Инструменты" }
}
```

Перечень кодов действий задан в `services/logService.js` и ограничен
словарём: произвольное название действия записать нельзя.
При превышении размера 512 КБ файл автоматически переносится в архив.

## Проверка исходных данных

Согласно требованиям проверка выполняется для всех входных значений.
Правила собраны в модуле `services/validationService.js`:

- **название** — от 2 до 120 символов, пустое значение не допускается;
- **адрес ресурса** — разбирается штатным классом `URL`, допускаются
  только схемы `http://` и `https://`; адрес без схемы дополняется
  автоматически; проверяется наличие доменного имени;
- **описание** — не более 500 символов;
- **тема** — проверяется существование записи в базе;
- **номер страницы** — приводится к допустимому диапазону;
- **порядок сортировки** — принимается только из заданного списка;
- **повторный адрес** — ссылка с существующим адресом не добавляется.

## Параметры приложения

Значения задаются переменными окружения и могут быть изменены
без правки исходного кода:

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `PORT` | `3000` | порт сервера |
| `ADMIN_LOGIN` | `admin` | логин администратора |
| `ADMIN_PASSWORD` | `admin123` | пароль администратора |
| `PER_PAGE` | `9` | количество карточек на странице |
| `SESSION_MAX_AGE` | `60` | время жизни сессии в минутах |
| `SESSION_SECRET` | — | ключ подписи сессионных данных |

Пример запуска на другом порту:

```bash
PORT=4000 npm start
```

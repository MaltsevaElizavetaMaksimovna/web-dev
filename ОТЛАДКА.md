# Лабораторная работа № 8. Отладка приложения

Задание: показать практические знания процесса отладки программы
(использование точек останова, контроль и изменение состояния переменных
и т. д.) в среде разработки и тестирования.

Документ содержит порядок действий и перечень мест в коде, удобных
для демонстрации приёмов отладки. Снимки экрана выполняются
при прохождении описанных сценариев.

---

## 1. Запуск приложения в режиме отладки

### Способ 1. Visual Studio Code

1. Открыть папку проекта в редакторе.
2. Перейти на вкладку **Run and Debug** (сочетание клавиш `Ctrl+Shift+D`).
3. В списке конфигураций выбрать **«Запуск с отладчиком»**.
4. Нажать клавишу `F5`.

Конфигурация описана в файле `.vscode/launch.json`.

### Способ 2. Отладчик браузера

```bash
npm run debug
```

Далее открыть в браузере Chrome адрес `chrome://inspect`
и выбрать процесс в разделе **Remote Target**.

---

## 2. Панель управления отладчиком

| Клавиша | Действие | Назначение |
|---|---|---|
| `F5` | Continue | продолжить выполнение до следующей точки останова |
| `F10` | Step Over | выполнить строку целиком, не заходя внутрь функции |
| `F11` | Step Into | перейти внутрь вызываемой функции |
| `Shift+F11` | Step Out | выйти из текущей функции |
| `Ctrl+Shift+F5` | Restart | перезапустить приложение |
| `Shift+F5` | Stop | завершить отладку |

## 3. Сценарий 1. Проверка исходных данных

**Цель:** показать, как значение проходит проверку и что происходит
при вводе некорректных данных.

### Порядок действий

1. Открыть файл `src/services/validationService.js`.
2. Поставить точку останова на строке с объявлением функции `validateUrl`
   (щелчок слева от номера строки — появится красная отметка).
3. Запустить отладку клавишей `F5`.
4. В браузере войти в панель управления и открыть страницу
   **Добавить ссылку**.
5. Заполнить поле адреса значением `javascript:alert(1)` и отправить форму.
6. Выполнение остановится на точке останова.

### Что показать на снимках экрана

**Раздел Variables** — текущие значения переменных:

- `raw` — исходное значение, полученное из формы;
- `value` — значение после удаления пробелов;
- `errors` — пустой массив на момент остановки.

**Пошаговое выполнение** — нажимая `F10`, пройти по строкам функции
и показать, как:

- выполняется проверка на пустое значение;
- значение разбирается конструктором `new URL(value)`;
- условие `ALLOWED_PROTOCOLS.includes(parsed.protocol)` даёт `false`;
- в массив `errors` добавляется сообщение об ошибке.

**Раздел Watch** — добавить выражения для наблюдения:

```
value
errors.length
parsed.protocol
```

**Изменение значения переменной.** В разделе Variables дважды щёлкнуть
по переменной `value`, ввести `https://example.com` и нажать `Enter`.
Продолжить выполнение клавишей `F5` — форма будет принята.
Этот приём демонстрирует влияние состояния переменной на ход программы.

## 4. Сценарий 2. Прохождение запроса по слоям приложения

**Цель:** показать перемещение данных между слоями и работу
раздела Call Stack.

### Порядок действий

1. Поставить точки останова в трёх файлах:
   - `src/routes/catalogRoutes.js` — первая строка обработчика маршрута `/`;
   - `src/services/linkService.js` — начало функции `getCatalogPage`;
   - `src/repositories/linkRepository.js` — начало функции `findAll`.
2. Открыть в браузере адрес `http://localhost:3000/?search=css&topic=3`.
3. Последовательно пройти все три остановки клавишей `F5`.

### Что показать на снимках экрана

**Первая остановка (маршрут).** В разделе Variables раскрыть объект `req`
и показать:

- `req.query` — параметры строки запроса: `{ search: 'css', topic: '3' }`;
- `req.method` — метод запроса `GET`;
- `req.path` — путь `/`.

**Вторая остановка (сервис).** Показать, как параметры приводятся
к безопасным значениям:

- `search` после вызова `normalizeSearch`;
- `topicId` после проверки существования темы;
- вычисление `totalPages` и `offset`.

**Третья остановка (репозиторий).** Показать формирование SQL-запроса:

- массив `conditions` с условиями выборки;
- объект `params` с подставляемыми значениями;
- итоговый текст запроса.

**Раздел Call Stack.** На третьей остановке показать цепочку вызовов:

```
findAll            (linkRepository.js)
getCatalogPage     (linkService.js)
<anonymous>        (catalogRoutes.js)
```

Щелчок по любой строке стека переключает контекст и позволяет
просмотреть переменные соответствующей функции.

## 5. Сценарий 3. Условная точка останова

**Цель:** показать остановку выполнения только при заданном условии.

### Порядок действий

1. Открыть файл `src/services/linkService.js`.
2. Найти функцию `handleRedirect`.
3. Щёлкнуть правой кнопкой слева от номера строки и выбрать
   **Add Conditional Breakpoint**.
4. Ввести условие:

```javascript
link && link.clicks > 300
```

5. Открывать в браузере разные ссылки каталога.

Выполнение остановится только при переходе по ссылке, у которой
количество переходов превышает 300 (например, GitHub или Stack Overflow).
На остальных ссылках остановки не произойдёт.

Этот приём применяется, когда ошибка проявляется лишь при определённых
значениях данных и обычная точка останова срабатывала бы слишком часто.

## 6. Сценарий 4. Отладка проверки пароля

**Цель:** показать работу с хешем пароля и защиту от подбора.

### Порядок действий

1. Открыть файл `src/services/authService.js`.
2. Поставить точку останова на строке с вызовом `bcrypt.compareSync`.
3. Открыть страницу входа и ввести неверный пароль.

### Что показать на снимках экрана

- `admin.password_hash` — хеш пароля из базы данных;
  открытый пароль в базе не хранится;
- `passwordMatches` — результат сравнения `false`;
- `failedAttempts` — содержимое карты неудачных попыток;
  после каждой неудачи счётчик увеличивается;
- после пяти неудачных попыток функция `checkBlocked` возвращает
  `{ blocked: true }` и вход временно запрещается.

## 8. Приёмы отладки, применённые в проекте

### Точки останова

Обычные, условные и точки с выводом сообщения (Logpoint).
Последние не останавливают выполнение, а выводят значение в консоль —
удобно при отладке циклов.

### Контроль состояния переменных

Раздел **Variables** показывает значения в текущей области видимости.
Раздел **Watch** позволяет наблюдать за произвольными выражениями.
Наведение указателя на переменную в коде показывает её значение
во всплывающей подсказке.

### Изменение состояния во время выполнения

Значение переменной можно изменить прямо в разделе Variables,
не останавливая программу. Приём применяется для проверки того,
как поведёт себя программа при других данных.

### Раздел Debug Console

Позволяет вычислять выражения в контексте остановленной программы:

```javascript
req.query
links.length
filters.search.toUpperCase()
```

### Обработка ошибок

В файле `src/app.js` предусмотрен обработчик ошибок, который
записывает сбой в журнал и выводит страницу с сообщением.
В режиме разработки на странице дополнительно отображается
стек вызовов — это упрощает поиск причины ошибки.
